# Step 3 results — bounded ingestion and local OCR

Verified 28 October 2026. Step 3 local acceptance gate passes on macOS arm64 / CPython 3.14.6. Shared production and other platforms still require their own resource measurements.

## Changed behavior

- FastAPI calls one parser per uploaded file. CSV/Excel frames supply both embedding text and typed table assets, avoiding the previous duplicate read.
- Missing numeric CSV/Excel cells retain nullable numeric dtypes. The `amount` fixture `[10, null, 30]` totals **40** and remains `Int64` in the tested Pandas environment.
- JSON, slides, table rows, and ordinary text all pass through the same chunk bound. The configured encoder tokenizer is used when present; an offline UTF-8 byte bound is the fallback. A 240-token content budget reserves room for special tokens under the current MiniLM 256-token input limit. Each chunk carries stable `source_id`, `chunk_id`, and `chunk_index` metadata alongside page/sheet/row references. IDs derive from source bytes/name and chunk content/position; the corpus version is still assigned by publication.
- Office archives reject more than 500 entries or 100 MiB declared expansion. PDFs reject more than 500 pages, presentations more than 500 slides, and parsed tables more than 100,000 rows. Empty-text PDFs return `ocr_required`; partially unreadable PDFs/slides return warnings in the upload response and UI.
- Upload parsing now runs in a short-lived child process with a 30-second wall deadline and at most two concurrent parser jobs per API process. The parent terminates timed-out workers, bounds the serialized result to 64 MiB, samples worker RSS at 50 ms intervals, allows at most 512 MiB growth above the post-startup baseline, and imposes a 1.5 GiB emergency ceiling. Baseline-relative accounting avoids false rejection when Python's spawn mode imports a heavy parent module. Linux workers also set a 2 GiB address-space limit. API timeout, unavailable, and OCR-configuration responses use stable error codes.
- Parent and child parser paths enforce a 10 MiB per-file input cap. Images are limited to 20 million pixels, 10 frames, and 1 million OCR characters. Tesseract calls have a four-second page timeout. PDF OCR renders at 200 DPI and processes at most five scanned pages per file; remaining pages are reported as partial extraction instead of silently omitted.
- Fully scanned PDFs now use local Tesseract when available, retain page and raster provenance, and publish searchable chunks. Local preprocessing applies EXIF orientation, grayscale autocontrast, median noise filtering, and bounded Tesseract orientation detection. `DOCQA_OCR_LANGUAGES` accepts installed Tesseract identifiers joined by `+`; missing packs fail with a redacted `ocr_not_configured` response. Image OCR handles bounded multi-frame inputs. A configured Google key does not send images to cloud OCR unless `DOCQA_ALLOW_CLOUD_OCR=true` is explicitly set.
- Embedding encoding uses an explicit batch size, default 32 and bounded to 1–256 through `EMBEDDING_BATCH_SIZE`. Batch size selects the cached runtime instance but is excluded from the coordinate-system fingerprint, so this operational tuning does not force an unnecessary corpus rebuild.
- JSON scalar values and empty containers now retain RFC 6901 pointer metadata through chunking and corpus storage. Structure traversal stops after 5,000 nodes or 64 levels. Duplicate values at distinct paths receive distinct chunk IDs.
- PDF text is grouped into blocks of up to eight lines. Blocks retain page, line range, top-origin bounding box, and page size; extraction stops after 20,000 lines. Fallback page text marks coordinates unavailable. Partial PDFs name pages needing OCR. Each uploaded source has a structured extraction report in the upload response and persisted `/api/state`.

## Evidence

The current offline suite passes **136 tests**. The diagnostic harness reports zero reproduced defects, one passing rejection control, and no probe errors. Isolated CSV and PDF parsing preserve typed tables, PDF coordinates, OCR provenance, and source reports across the process boundary. Tests exercise the RSS kill path, baseline-relative growth policy, Linux limit call, two-slot parser ceiling, embedding batch validation, OCR preprocessing, and missing-language error. A forced deadline ends the child; an API timeout preserves the previous corpus version. API upload tests publish a scanned PDF as searchable text with its OCR report. Upload/publish/reload tests retain the last fact in long JSON with its `/body` pointer, plus PDF bounding boxes and reports in stored FAISS documents and corpus state.

`python3 -m tools.measure_ingestion` ran six fresh parser processes with real local Tesseract. All expected tail/OCR fragments survived. Observed wall time / peak worker RSS: representative text **0.284s / 110.6 MiB**, 10,000-row CSV **0.398s / 116.4 MiB**, 2,800-value JSON **0.300s / 113.6 MiB**, one-page scanned PDF **0.469s / 144.1 MiB**, rotated image **0.614s / 142.4 MiB**, and noisy image **0.420s / 115.7 MiB**. Running the scanned PDF and rotated image together took **1.006s** with a conservative summed peak of **286.7 MiB**. Encoding 256 documents with cached 384-dimensional MiniLM, batch 32, took **2.329s** with **595.4 MiB** peak process RSS. These are synthetic current-machine measurements, not production SLOs.

## Limits after the local gate

- PDF coordinates identify text blocks, not exact positions of every generated token chunk. Rotation and noise checks are generated English controls, not a representative quality benchmark. Multilingual text, handwriting, camera distortion, and slide images still need held-out evaluation; this machine currently has only `eng`, `osd`, and `snum` Tesseract data.
- macOS now has sampled parser RSS growth and emergency guards, but process sampling can miss short spikes and sandbox permissions can prevent descendant enumeration. Linux's hard 2 GiB address-space call is unit-verified but was not exercised by this macOS run. Embedding and two-parser memory were measured separately, not as a full API process-tree load test. Production latency/concurrency and parent-side vector publication remain Step 10 work.
- Five-page PDF OCR cap is deliberate. Larger scanned files produce explicit partial warnings and require splitting or a future durable OCR job.
- Warning messages now survive reload with their corpus version. Legacy Streamlit still calls compatibility wrappers separately.
- The tokenizer budget is based on current MiniLM settings. Step 4 persists and validates encoder/tokenizer identity for new corpora, including local real-model checks.
- Chrome synthetic preview confirmed initial state, suggested-question chat with source evidence, replacement upload, and a partially blank PDF warning in the live interface. A follow-up browser check confirmed the warning remains visible after page reload. Mobile layout remains unverified in this slice; the known narrow-viewport defect from Step 2 remains open.
